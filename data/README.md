# data — 파일과 컬럼 정의

이 폴더의 파일만 보고도 무엇이 관측이고 무엇이 판단인지 구분할 수 있어야 한다.
사람이 읽든 AI가 읽든 **다른 파일을 찾아가지 않고 여기서 끝나도록** 쓴다.

> ⚠️ 2026년 8월 특정 시점의 관측이다. 이미 개선되었을 수 있다.
> 지원자 개인 분석 · 공개 데이터 기반 · 카카오뱅크와 무관.

## 파일

| 파일 | 무엇인가 | 만든 방법 |
|---|---|---|
| `seeds.csv` | 시드 질문 24개 | 사람이 작성. 상품명은 앱에서 실재 확인 |
| `goldenset.csv` | 골든셋 60문항 | 사람이 작성 |
| `observations-round1.csv` | **1라운드 관측 기록 97턴** | 사람이 관측, Claude가 요약·판정 (아래 「누가 무엇을 썼나」) |
| `observations-round2.csv` | **2라운드 관측 기록** (진행 중) | 같음 |

판단 근거와 그 대가는 [`../docs/05-공개목록.md`](../docs/05-공개목록.md)에 적었다.

## 관측 기록 CSV

`observations-round1.csv`는 **13컬럼**, `observations-round2.csv`는 **19컬럼**이다.
1라운드 컬럼은 순서까지 그대로 두고 2라운드에서 6개를 더했다.
**한 행이 한 턴**이고, 한 대화(회차)는 최대 5행이다.

### 공통 13컬럼

| 컬럼 | 값 | 뜻 |
|---|---|---|
| `seed_id` | `S01`~`S24` | 시드 질문 번호. `seeds.csv`와 대응 |
| `round` | 정수 | **그 시드를 몇 번째로 관측했나.** 프로젝트 라운드 번호가 아니다 — 2라운드 작업에서 새로 만든 시드는 `1`이다 |
| `turn` | `1`~`5` | 한 대화 안의 턴 번호 |
| `입력질문` | 자유 문자열 | 그 턴에 **실제로 보낸 문장**. 1턴은 시드 질문, 2턴부터는 따라간 추천 문구 그대로 |
| `답변요약` | 자유 문자열 | **답변 원문을 읽고 쓴 요약.** AI 답변 원문 자체가 아니다 (아래 「누가 무엇을 썼나」) |
| `근거표시` | `기준일` `링크` `출처명` `X` | 답변이 근거를 어떤 형태로 붙였나. 딥링크 카드는 여기 포함되지 않는다(아래 `앱기능_진입`) |
| `한계고지` | `O` `X` `해당없음` | 답변이 **스스로** 불완전성·조건부성을 밝혔나. 밝힐 것이 없는 답이면 `해당없음` |
| `노출된_추천_전부` | ` / ` 로 구분 | 그 턴에 뜬 추천 문구 전부. 없으면 `없음` |
| `클릭한_추천` | 자유 문자열 | 다음 턴에 보낸 것. 5턴이면 `(5턴 종료)` |
| `앱기능_진입` | `O` `X` | **딥링크 카드 또는 다른 기능 진입이 있었나** |
| `진입한_기능명` | 자유 문자열 | 있으면 이름. 상품 화면이면 `모임통장(상품화면)` 처럼 표기 |
| `판정` | `정답` `부분` `오답` `거절` `무응답` | 아래 정의 |
| `메모` | 자유 문자열 | 판정 근거와 검증 대상. **관측이 아니라 분석이다** |

### 2라운드에서 더한 6컬럼

| 컬럼 | 값 | 뜻 | 왜 생겼나 |
|---|---|---|---|
| `목적` | `재현성` `분기탐색` `인계조건` | **이 회차를 왜 관측하는가** | 데이터만 보고는 S01을 왜 두 번 돌렸는지 알 수 없었다. 관측 결과가 아니라 설계 의도이므로 계산으로 나오지 않는다 → 컬럼으로 만든다 |
| `인계여부` | `O` `X` | 대화가 **다른 창으로 넘어갔나** | `앱기능_진입`과 다르다. 1라운드에서 카드 없이 넘어간 턴이 3개 있었다 |
| `기능안내` | `O` `X` `해당없음` | 넘어가진 않았지만 **그런 기능이 있다고 말은 했나** | *"인계하지 않는 것은 설계일 수 있으나 안내하지 않는 것은 개선 여지"* — 한 칸에 적으면 이 구분이 사라진다 |
| `되묻기` | `O` `X` | AI가 **역질문했나** | 되묻기는 추천이 아니다. 「첫 번째 추천을 따라간다」 규칙은 추천 블록에만 적용한다 |
| `딥링크_개수` | 0 이상 정수 | 그 턴의 카드 수 | 1라운드는 O/X로만 셌는데 한 시드가 `3→2→1→0→0`으로 단조 감소했다. 개수가 아니면 안 보인다 |
| `답변원문파일` | 경로 | 그 회차 원문 파일 | 1라운드에서 원문을 파일로 남기지 않아 채점기 입력이 사라진 적이 있다. **비면 눈에 띄도록** 칸으로 만들었다 |

> **`분기` 컬럼은 일부러 만들지 않았다.** 몇 번째 추천을 눌렀는지는
> `노출된_추천_전부`에서 `클릭한_추천`의 위치를 찾으면 나온다.
> 사람이 또 적으면 두 값이 어긋날 수 있다.
> **계산되는 것은 컬럼으로 만들지 않고, 계산되지 않는 것만 컬럼으로 만든다.**

### `판정` 5종

| 값 | 뜻 |
|---|---|
| `정답` | 내용이 맞다 |
| `부분` | 틀리지는 않았는데 빠졌거나, 범위를 밝히지 않았다 |
| `오답` | 틀렸다 |
| `거절` | 답하지 않는 것이 옳은 질문에 답하지 않았다 |
| `무응답` | 답이 오지 않았다 (1라운드 미관측) |

🔴 **금리·한도처럼 앱에 범위가 공시된 항목은 3단계로 나눈다.**
공시 범위를 밝히고 심사 고지를 붙였으면 `정답`, 범위를 빠뜨렸으면 `부분`,
특정 수치를 단정했으면 `오답`.

## 읽을 때 주의할 것

**① `답변요약`은 카카오뱅크 AI가 쓴 글이 아니다.** 답변 원문을 읽고 요약한 것이다.
카카오뱅크 AI가 실제로 쓴 문장은 `scored-round1.public.json`의 `발췌`에만 있고, 그것도 일부다.
누가 요약했는지는 바로 아래 절을 볼 것.

**② 1라운드 `노출된_추천_전부`의 구분자가 두 가지다.**
S01·S02 여섯 턴은 ` | `, 나머지 91턴은 ` / `를 썼다.
**고치지 않았다** — 관측 기록의 글자를 나중에 바꾸지 않는다는 규칙 때문이다.
파싱한다면 두 구분자를 모두 받아야 한다. 2라운드는 ` / `로 통일했다.

**③ 도달 수치가 두 개다.**
`앱기능_진입 = O` 인 턴은 61개인데, 답변 원문에서 딥링크 URL이 파싱되는 턴은 58개다.
차이 3건은 **카드 없이 도달한 경우**다 — 한 건은 원문이 스크린샷 전사본이라 URL이 없고,
두 건은 딥링크가 아니라 다른 창으로 이관된 경우다. 둘 다 맞는 수치이고 **세는 대상이 다르다.**

**④ 빈 행은 미관측이다.** 기록지를 미리 만들어 두므로, 체인이 일찍 끝나면 아래 행이 빈 채로 남는다.
`판정`이 비어 있으면 그 턴은 관측되지 않은 것이다.

## 🔴 누가 무엇을 썼나 — 이 저장소에서 가장 먼저 밝혀야 할 것

이 프로젝트는 **AI가 만드는 것을 돕는 도구로 AI를 썼다.** 그 경계를 흐리면 안 된다.

| 무엇 | 누가 |
|---|---|
| 앱을 조작하고 시드를 던지고 추천을 따라간 것 | **사람** |
| 답변 원문을 복사해 넘긴 것 | **사람** |
| 화면에서만 알 수 있는 사실 — 다른 창으로 넘어갔는가, 텍스트 복사가 됐는가, 피드백 UI가 어떻게 동작하는가 | **사람** |
| 시드 24개·골든셋 60문항 설계, 판정 기준과 프로토콜 | **사람** (기록은 `docs/`) |
| `답변요약` · `판정` · `근거표시` · `한계고지` · `메모` | **Claude가 답변 원문을 읽고 작성** |
| 채점 룰 6종과 그 결과 | **코드** (`tools/`) |

**즉 `판정` 칸은 사람이 한 줄 한 줄 직접 매긴 것이 아니다.** Claude가 원문을 읽고 붙였고,
사람은 대화 중에 그것을 보고 필요할 때 교정했다.

### 이게 왜 중요한가 — 결론 하나가 약해진다

*"사람이 손으로 찾은 발견을 룰 기반 채점기가 전부 재현했다"* 고 쓰면 과장이다.
정확히는 **"대화 중 원문을 읽으며 눈으로 찾은 것을, 결정적인 룰이 재현했다"** 이고,
양쪽 모두 같은 계열의 판단자다.

그래도 남는 값어치는 있다 — 눈으로 읽는 것은 **회차마다 결과가 달라지고 재현되지 않는다.**
룰은 같은 입력에 항상 같은 결과를 낸다. **비교되는 것은 "사람 대 기계"가 아니라 "비결정적 판독 대 결정적 판독"이다.**
이게 D-02(채점은 룰 주력)의 실제 근거다.

🔴 **골든셋은 다르게 간다.** 정답은 사람이 직접 붙인다 (D-03).
관측 판정과 달리 골든셋은 **채점기를 믿을 수 있는지의 기준선**이 되어야 하기 때문이다.

## 생성·검증

```bash
node tools/lib/csv.mjs      # CSV 파서 자체검증 (파싱 · 왕복)
node tools/make-round2.mjs  # 2라운드 기록지 생성 — 이미 기록이 있으면 중단한다
node tools/score.mjs        # 채점 → scored-round1.json(로컬) + .public.json(공개)
```

CSV를 고친 뒤에는 행수·컬럼수를 반드시 확인한다.
메모 칸에 쉼표와 따옴표가 들어 있어 **단순 분리로는 파싱되지 않는다** (`tools/lib/csv.mjs` 사용).
