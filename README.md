# reachmap

**대화형 AI 답변 품질 검증 도구와, 그 도구로 실제 서비스를 관측한 기록.**

> 지원자 개인 분석 · 공개된 앱을 직접 써본 기록 · **카카오뱅크와 무관**
> 2026년 8월 17~21일 관측이며, 이미 개선되었을 수 있다.

### ▶ [**대시보드 열기**](https://junhee8649.github.io/reachmap/) · [**리포트**](docs/08-리포트.md) (약 10분) · [상세본](docs/09-리포트-상세.md)

## 한 줄로

카카오뱅크 앱 `AI 검색`에 질문 **204개**를 넣고 답변을 저장한 뒤,
**같은 입력이면 같은 결과가 나오는 검사기**를 만들어 훑었다.

| | |
|---|---|
| 내용이 맞은 턴 | **92%** (정답 187 · 부분 11 · 오답 3 · 거절 1 · 미판정 2) |
| **상품·기능에 도달한 턴** | **63%** (129턴) |
| 계산이 주제였던 시드 3개(15턴) | 상품 링크 **0회** |

**이 격차가 주제다.** 담당자가 인터뷰에서 밝힌 목표는 *"상품 페이지로 연결되는 클릭률 30%"* 이고,
그렇다면 재야 할 것은 정확도가 아니라 **도달(reach)** 이다.

## 공고의 담당업무와 어디서 만나나

| 담당업무 | 여기서 | 무엇을 했나 |
|---|---|---|
| AI 데이터 모니터링 | [`docs/03`](docs/03-관측-프로토콜.md) | 관측 SOP를 쓰고 204턴을 기록·판정했다 |
| **AI 답변 검증** | [`tools/`](tools/) | 룰 6종 채점기. 답이 매번 달라도 회차끼리 비교되게 **결정적**으로 만들었다 |
| **RAG 문서 생성·관리** | [`docs/07`](docs/07-RAG-문서실험.md) | FAQ를 **내용은 그대로 두고** 다시 써서 검색을 재측정했다 |
| **선제안/추천 질문 운영** | [리포트](docs/08-리포트.md) | 추천이 대화를 넓히지 않는 형태 4가지 + 태그 91개 중 추천이 닿은 16개 |
| 고객 피드백 모니터링 | [`tools/feedback.py`](tools/feedback.py) | 리뷰 수집은 접었다(robots.txt). 대신 **앱 안 피드백 UI의 분류**로 재집계했다 |

RAG 실험은 **주제 두 개(10건 + 16건)에서 재현**했고, 2차에서 **1차 설계가 부풀려져 있었음을 찾아**
훈련/검증을 나눴다. 우대사항인 **Python·SQL**은 `tools/feedback.py` 에 있다 — 채점 결과를
SQLite 인메모리에 넣고 집계 질의 4개로 뽑는다.

## 어떻게 관측했나

| 방식 | 무엇 | 규모 |
|---|---|---|
| **추천 질문 경로** | 매 턴 **첫 번째 추천만** 따라가며 5턴까지 | 33회차 **144턴** |
| **골든셋** | 정답을 미리 정한 문항을, 문항마다 대화를 초기화해 1턴씩 | **60문항** |
| 선제안 | 홈 화면 토스트를 눌러서 (204턴에 넣지 않았다) | 3건 |

두 방식은 **전제가 다르다.** 골든셋은 턴이 이어지지 않으므로 「앞 턴의 단서가 떨어졌나」 같은
룰을 그대로 돌리면 오탐이 난다. 실제로 냈고, 그래서 **채점기를 둘로 나눴다.**

## 무엇으로 채점했나

답변 원문에 룰 6종을 돌린다. 전부 문자열·산술 대조라 **같은 입력이면 같은 결과**가 나온다([D-02](docs/02-결정기록.md)).
잡힌 221건을 **사용자가 볼 수 있는지**로 갈랐다.

```
A 신고 가능   59건   기준일없음 32 · 예시휘발 16 · 공시범위밖 9 · 내부용어 1 · 표검산 1
B 칸이 없다   32건   글자까지 같은 추천 재탕 — 사용자는 보는데 신고할 칸이 없다
C 안 보인다  130건   마크다운 헤더 공백 — 앱에서는 정상 렌더된다
```

**C층은 결함으로 세지 않는다.** 처음에는 전부 묶어 227건이라고 썼는데, 확인해보니 절반 이상이
이것이었고 앱에서는 제목으로 정상 렌더된다. **숫자를 부풀린 것이라 층을 나눴다.**
탐지는 채점기에 남겨 뒀다 — 지우면 130건을 아무도 재현할 수 없다.

## 이 도구가 못 잡는 것

- **의미가 같고 문구만 다른 추천**을 재탕으로 못 잡는다.
  `회비 미납한 **사람**` ↔ `회비 미납 **멤버**` 를 0건으로 흘린다
- **딥링크가 떴지만 답의 핵심이 아닌 상품**을 가리킨 경우를 도달 성공으로 센다
- **딥링크 없이 다른 기능으로 이관된 턴**을 원문에서 못 센다 (카드가 없다)
- 이관된 창은 **텍스트 복사가 안 돼** 직접 옮겨 적었다. 그 턴은 문자열 판정에서 제외했다
- **룰은 AI 답변의 형식에 맞춰져 있다.** 같은 룰을 **원본 FAQ 본문 38건**에 돌리면 0건이다 —
  문서에 결함이 없어서가 아니라 룰이 보는 자리가 다르기 때문이다

## 무엇을 공개하지 않나

카카오뱅크 AI 답변 **원문 전량은 올리지 않는다.** 204턴 약 51만 자를 통째로 올리는 것은
인용이 아니라 재배포에 가깝다고 봤다. 대신 요약과 **룰이 잡은 자리 주변 발췌**를 싣는다.

그러면 남이 채점기를 확인할 수 없으므로 **대화 하나(`data/raw/round1/S10.txt`)만 원문째로 올렸다.**
그 파일 하나로 `node tools/score.mjs 1` 이 돌고 룰 세 종이 그대로 걸린다.
판단과 그 대가는 [docs/05](docs/05-공개목록.md)에 적었다.

## 실행

```bash
npm install && npm run dev     # 대시보드
node tools/rag.mjs --v2        # RAG 문서 실험 (키워드 검색기 — 여기서 그대로 재현된다)
node tools/score.mjs 1         # 채점기 — 공개한 원문 1건(S10)만 채점된다
node tools/check.mjs           # 문서에 적힌 숫자를 데이터와 대조한다
```

임베딩 검색기는 `GEMINI_API_KEY` 가 있어야 돌고, 원문이 필요한 나머지 도구는 여기서 돌지 않는다.
어느 것이 돌고 어느 것이 안 도는지는 [상세본의 「재현 방법」](docs/09-리포트-상세.md)에 표로 적었다.
