# reachmap

**대화형 AI 답변 품질 검증 도구와, 그 도구로 실제 서비스를 관측한 기록.**

> 지원자 개인 분석 · 공개 데이터 기반 · **카카오뱅크와 무관**
> 2026년 8월 특정 시점의 관측이며, 이미 개선되었을 수 있다.

---

## 이름의 뜻

이 종류의 서비스에서 중요한 지표는 정확도가 아니라 **도달(reach)** 이라고 봤다.
답이 맞아도 사용자가 상품·기능에 닿지 못하면 서비스로서는 절반만 성공한 것이다.

관측 결과가 그 가설과 같은 방향이었다.

| | |
|---|---|
| 내용이 맞은 턴 | **91%** (97턴 중 정답 88) |
| 상품·기능에 도달한 턴 | **63%** (61턴) |
| 계산 주제 시드 3개(15턴)의 딥링크 | **0회** |

`map`은 **커버리지 히트맵**을 가리킨다. 추천 체인 자체는 지도가 아니라 그래프다.

---

## 무엇을 했나

카카오뱅크 앱의 AI 검색에 시드 질문 22개를 넣고, **매 턴 첫 번째 추천 질문만** 따라가며
최대 5턴까지 대화를 이어갔다. 총 **97턴**을 관측했다.

그 답변 원문에 **결정적 룰 6종**을 돌려 채점했다. 룰은 전부 문자열·산술 대조이므로
같은 입력이면 항상 같은 결과가 나온다 — 회귀 비교가 성립하려면 채점기가 결정적이어야 한다는 판단이다
([D-02](docs/02-결정기록.md)).

```
헤더공백      마크다운 헤더에 공백이 없어 렌더러에 따라 헤더로 안 잡힌다
내부용어      "문서에 …" 처럼 RAG 문서의 존재가 답변 표면에 드러난다
예시휘발      앞 턴에서 (예시)라고 밝힌 숫자가 뒤 턴에서 단서 없이 재등장한다
기준일없음    금리를 말하면서 기준일을 붙이지 않는다
표검산        답변이 그린 표 안에서 원금 + 이자 ≠ 합계
공시범위밖    앱 공시 범위를 벗어난 금리를 예시로 쓴다
```

답변을 읽어가며 눈으로 찾았던 발견 7건을 도구가 전부 재현했고, **마크다운 헤더 문제는 훨씬 넓게 찾았다**
(눈으로 볼 때 3개 시드 → 도구 12개 시드 79건).

> ⚠️ 여기서 **"사람 대 기계"라고 쓰지 않는다.** 관측 기록의 요약과 판정은 Claude가 답변 원문을
> 읽고 붙인 것이고, 사람이 한 줄씩 직접 매긴 것이 아니다. 비교되는 것은
> **비결정적 판독과 결정적 판독**이다 — 눈으로 읽으면 회차마다 결과가 달라지고,
> 룰은 같은 입력에 항상 같은 결과를 낸다. 누가 무엇을 썼는지는 [data/README.md](data/README.md)에 표로 적었다.

## 무엇을 못 하나

리포트에 「이 도구가 못 잡는 것」을 반드시 넣기로 했다. 지금까지 확정된 것:

- **의미가 같은데 문구만 다른 추천**을 재탕으로 못 잡는다. 한 시드는 문자열 일치 0건인데 의미 중복이 3계열이었다
- **딥링크가 떴지만 답의 핵심이 아닌 상품**을 가리킨 경우를 도달 성공으로 센다
- **딥링크 없이 다른 기능으로 이관된 3턴**을 룰이 못 센다 (원문에 카드가 없다). 그래서 도달은 58이 아니라 61이다
- 이관된 창은 **텍스트 복사가 되지 않아** 관측자가 직접 옮겨 적었다. 그 턴은 재탕 판정(문자열 일치)에 쓸 수 없다

## 무엇을 공개하지 않나

카카오뱅크 AI 답변 **원문 전량은 올리지 않는다.** 인용이 아니라 재배포가 되기 때문이다.
대신 관측자가 쓴 요약과, 룰이 잡은 자리 앞뒤 발췌(원문의 16%)를 싣는다.

그 대가로 **남이 이 저장소만 받아서 채점기를 재실행할 수는 없다.** 판단 근거와 함께
[docs/05-공개목록.md](docs/05-공개목록.md)에 적어두었다.

## 실행

```bash
npm install
npm run dev      # 대시보드
npm run score    # 채점기 — 원문이 있어야 돈다 (공개본에는 없다)
```
