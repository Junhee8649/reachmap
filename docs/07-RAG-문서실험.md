# RAG 문서 실험 — 문서를 어떻게 써야 검색되는가

> **1차** 2026-08-19 · 자동이체 가져오기 FAQ **10건** (절차 문서)
> **2차** 2026-08-21 · 26주적금 FAQ **16건** (상품 문서) — 다른 주제에서 재현되나 보려고
> 둘 다 D-09가 정한 통장/저축 안이다.
> 재현: `node tools/rag.mjs [--묶음=적금] [--v2] [--임베딩]`
>
> 🔴 **1차 수치는 훈련/검증을 나누기 전에 잰 값이다.** 2차에서 그 사실을 발견해 분할을 도입했다.
> 아래 1차 결과를 지우지 않고 두되, 어느 값이 어떤 조건에서 나온 것인지 함께 적는다.

## 왜 이 주제인가

공고 담당업무는 「AI 답변 품질 개선을 위한 **RAG 문서 관리**」다.
이 팀은 모델을 못 건드리고 **문서와 추천 질문 콘텐츠**를 손댄다. 그러면 물어볼 것은 하나다 —
**문서를 어떻게 써야 AI가 찾아 쓰는가.**

자동이체 가져오기를 고른 이유는 세 가지다.
① 문항이 10개로 작아 전수 실험이 된다 ② D-09가 정한 통장/저축 안이다
③ **우리 관측 S06이 정확히 이 주제**라 AI가 이 문서들을 어떻게 썼는지 대조할 수 있다.

## 실험 설계

```
문서   원본 10건 (카카오뱅크가 쓴 그대로)  vs  v2 10건 (우리가 다시 씀)
질의   21개 — 시드 1 · 추천 문구 10 · FAQ 제목 10
정답   사람이 붙임 (D-03). 원본만 보고 붙였고 재작성 전에 고정
검색   ① 문자 bigram TF-IDF (의존성 0, 완전 결정적)
       ② gemini-embedding-001 (taskType 분리 · 캐시로 결정성 확보)
```

🔴 **라벨을 먼저 얼린 이유**: 재작성한 문서에 맞춰 정답을 고치면 실험이 성립하지 않는다.
🔴 **v2는 사실을 하나도 바꾸지 않았다.** 우리는 은행이 아니다. 수치·조건·경로를 그대로 옮기고
**표현과 구조만** 바꿨다. 원칙은 쓰기 전에 `data/rag/docs-v2/_원칙.md`에 고정했다.

### 질의 21개가 어디서 왔나 — 이게 이 프로젝트의 자산이다

사용자 질의 로그는 우리에게 없다. 대신 **관측 144턴에서 AI가 실제로 화면에 띄운 추천 문구 411개**가 있다.
S06 한 시드에서만 15개(고유 10개)가 이 주제에 걸려 있다.
**FAQ 제목(카뱅이 쓴 말)과 추천 문구(AI가 쓴 말)를 갈라서 재는 것**이 이 실험의 핵심 장치다.

### 🔴 원본 문서는 자기 제목으로 물을 때만 완벽하다

키워드 검색에서 **FAQ 제목 10/10, 추천 문구 4/7**이었다.
같은 사실을 묻는데 **말투가 바뀌면 43%가 엉뚱한 문서를 1위로 뽑는다.**

못 맞힌 셋이 전부 진단적이다.

| 질의 | 정답 | 실제 1위 | 왜 |
|---|---|---|---|
| `자동이체 가져오기는 뭐야?` | D1 | D3 (**8위**로 밀림) | D1은 715자에 ※ 8개. **긴 문서가 오히려 불리하다** |
| `가져오기 신청은 어디서 해?` | D2 | D4 | D4가 「신청**결과**」를 갖고 있어 **어휘를 공유**한다 |
| `안 될 때 흔한 이유가 뭐야?` | D7 | D3 | D7 제목이 `가져오기가 안돼요` — **사용자 말과 겹치는 부분이 짧다** |

→ v2에서 **「이렇게도 물어봐요」 한 줄**을 넣고 어휘를 구별하자 **7/7**이 됐다.

### 🟢 그런데 임베딩은 원본에서도 이미 100%였다

**좋은 검색기 아래서는 문서 품질 차이가 안 보인다.** 이건 v2가 무의미하다는 뜻이 아니라,
**어떤 검색기를 쓰느냐가 「문서를 얼마나 잘 써야 하는가」를 정한다**는 뜻이다.
문서 10건짜리 소규모라 임베딩이 쉽게 만점을 낸 것일 수도 있다 — **표본 한계로 적어둔다.**

### 🔴 v2가 잃은 것도 있다 — 숨기지 않는다

| 잃은 것 | 원인 |
|---|---|
| FAQ 제목 Top-1 10/10 → **9/10** | D3·D6에 **상호 참조**(「이중 출금도 확인하세요」)를 넣자 두 문서가 서로 경쟁 |
| 임베딩의 「없음」 판별 여유 0.048 → **0.036** | 문서를 사용자 말투로 쓰니 **무관한 질문도 함께 가까워졌다** |

→ **사용자에게 친절한 문서가 검색에는 불리할 수 있다.** 트레이드오프이지 개선의 부작용이 아니다.

### 🔴 「답이 없는 질문」을 아는가 — 금융에서 더 중요한 축

정답 문서가 없는 질의 4개(`자동이체 등록`·`일시정지`·`해지`·`출금 우선순위`)를 섞어 넣었다.
검색기는 **언제나 1위를 내놓는다.** 그게 답이 아닐 때 걸러낼 수 있어야 한다.

| | 정답 있는 질의 최저 | 없는 질의 최고 | 문턱을 둘 수 있나 |
|---|---|---|---|
| 키워드 (원본) | 0.093 | 0.143 | 🔴 **겹친다** |
| 키워드 (v2) | 0.169 | 0.174 | 🔴 겹친다 |
| 임베딩 (원본) | 0.816 | 0.768 | 🟢 여유 0.048 |
| 임베딩 (v2) | 0.810 | 0.774 | 🟢 여유 0.036 |

→ **키워드는 두 번 다 겹쳤다.** 문턱 하나로 「모르겠다」를 만들 수 없다.
→ 임베딩은 갈렸지만 **여유가 얇고 문서 10건 기준**이다. 문서가 2,893개로 늘면 유지될 근거가 없다.
→ **D-05(둘 다 만들어 비교)가 옳았다는 실측이다.** 재현율은 임베딩이, 「없음」 판정은
둘 다 불안하다는 것이 수치로 나왔다.

## 🔴 2차 실험 (2026-08-21) — 다른 주제에서 다시 했고, 1차 결과를 깎았다

1차는 **한 주제 한 번**이었다. 그래서 두 번째 묶음을 골랐다 — **26주적금 FAQ 16건.**
자동이체 가져오기가 **절차 문서**인 반면 이쪽은 **상품 문서**다. 성격이 달라야 「주제가 달라도 되나」에 답이 된다.

질의는 31개다 — 관측에서 실제로 화면에 뜬 **26주적금 추천 문구 15개** + FAQ 제목 16개.

### 🟢 재현됐다 — 원본 문서의 약점이 같은 모양으로 나온다

```
                        FAQ 제목        사용자 말투
자동이체 (절차 10건)     10/10  100%      4/7   57%
적금     (상품 16건)     16/16  100%      5/9   56%
```

**주제도 문서 성격도 다른데 거의 같은 숫자다.** *"카뱅이 쓴 말로는 완벽한데 사용자가 쓰는 말로는 절반"* 이
한 번의 우연이 아님을 뜻한다. **이 실험에서 가장 단단한 결과다.**

### 🔴 그런데 1차의 개선폭은 부풀려져 있었다

1차에서 문서에 넣은 `이렇게도 물어봐요` 문구가 **시험 질의와 글자까지 같았다.**
답을 문서에 적어놓고 시험을 본 셈이라 점수가 과장된다.

2차는 **쓰기 전에 질의를 갈랐다.** 분할은 `data/rag/queries-적금.csv`의 `분할` 칸에 고정했고,
문서를 쓸 때 **검증용 4개는 열지 않았다.**

```
                        원본      재작성
FAQ 제목               16/16  →  16/16     원래부터 완벽
작성용 (문서에 넣음)     4/5  →   5/5
검증용 (안 넣음)        1/4  →   2/4      ← 이쪽이 진짜 실력
```

**고친 효과는 양쪽 다 +1건으로 같다.** 다른 것은 **출발점**이다 — 작성용은 이미 4/5였고 검증용은 1/4였다.

→ **1차의 `4/7 → 7/7` 은 훈련 문구를 포함한 값이다.** 이 문서에서 그 수치를 지우지 않고 두되,
**분할 없이 잰 값**임을 여기에 밝힌다. 소급해 다시 재지 않는 것은 1라운드 판정과 같은 원칙이다.

### 🔴 못 고친 2건은 문서 문제가 아니었다

```
26주적금 중간에 해지하면 이자가 얼마나 줄어들어?      X → X
26주적금에서 자동이체 한 번 실패하면 이자 차이가?      X → X
```

둘 다 **「얼마나」를 묻는데 문서에 수치가 없다.** 우대금리 값이 *"가입일 당시 게시된 값"* 이라
어느 문서에도 적혀 있지 않다.

→ **문서를 아무리 잘 써도 없는 사실은 못 찾아준다.** 이건 작성의 문제가 아니라 **커버리지 공백**이고,
처방이 다르다 — 다시 쓰는 게 아니라 **문서를 새로 채워야 한다.**

### 어떻게 올랐나 — 한 건을 끝까지 따라가면

`26주적금 가입은 어디에서 해?` (검증용, 정답 E6)

```
원본     1위 E7(해지) 0.142 · 2위 E13 0.125 · 3위 E6(가입) 0.097   틀림
재작성   1위 E6(가입) 0.276 · 2위 E7      0.129 · 3위 E13 0.125   맞음
```

v2에서 두 가지를 했다 — **(A)** 관측에 뜬 문구를 문서에 넣고,
**(D)** E6은 「새로 가입」, E7은 「이미 가입한 것을 해지」로 어휘를 갈랐다. 점수가 0.097 → 0.276으로 올랐다.

🔴 **왜 원본에서 E7이 이겼는지는 미상으로 둔다 (2026-08-22 교정).**
처음에는 *"원본 E6에는 `어디`·`에서` 가 아예 없어서"* 라고 적었는데 **사실이 아니다.**

```
「어디에서」   E6 없음 · E7 없음        둘 다 없다
「에서」       E6 있음(카카오뱅크에서) · E7 있음(홈 화면에서 / 출금·해지에서)
```

`에서` 는 16문서 중 2개에만 있어 가중치가 큰 조각이고 **E7이 더 많이 갖고 있다** — 그것이 원인일 수 있으나,
같은 식을 손으로 재현하니 순위가 달라져(`E13 > E6 > E7`) **단정할 수 없다.**
확실한 것은 **무엇을 바꿨고 점수가 어떻게 움직였나**까지다. 원인은 쓰지 않는다.

## 🔴 그리고 이게 가장 중요한 결과 — 결함의 출처를 갈랐다

우리 채점 룰 6종을 **카카오뱅크 원본 문서 10건에 그대로 돌렸다. 0건이었다.**
룰이 AI 답변의 형식(마크다운 헤더·`(예시)` 표기·표 검산)에 맞춰져 있어서다.
→ **도구의 적용 범위가 좁다는 실측**이고, 「이 도구가 못 잡는 것」에 들어간다.

그런데 문서를 직접 읽으니 결함이 있었고, **관측에서 잡은 것과 대조하니 출처가 갈렸다.**

| 관측에서 잡은 결함 | 문서를 보니 | 어시스턴트가 고칠 수 있나 |
|---|---|---|
| S06 3턴 *"앱 버전이 2.41 미만이라"* — 기준일 없음 | 🔴 **문서에 그대로 있다** (`2.41 버전 이상`, 기준일 없음) | ✅ **문서를 고치면 된다** (v2 D8에서 기준일 추가) |
| 이용시간 표기 흔들림 | 🔴 **문서 안에서 갈린다** — D1 `09시 ~ 22시` vs D5 `9시~22시` | ✅ v2에서 통일 |
| S08·S20 앱 경로 접두어 **6갈래** | 🟢 **문서는 4/4 완전 일치** (`홈 화면 오른쪽 하단 전체탭( ··· ) >`) | ❌ **모델이 만든 것.** 문서로는 못 고친다 |
| S04 26주적금 `26×7=182일` | 🟢 문서는 **`계약기간 6개월 고정`** 이라고 못박는다 | ⚠️ **문서는 있는데 그 줄에 닿지 못했다** |

→ **AI는 문서를 정확히 옮겼다.** 기준일이 없는 것은 문서다.
→ 반대로 경로 표기를 흔든 것은 **문서가 아니라 모델**이다. 문서는 이미 통일돼 있었다.
→ **이 구분이 없으면 개선 제안이 헛다리를 짚는다.** 문서를 고쳐도 안 고쳐지는 것이 있고,
문서 한 줄로 고쳐지는 것이 있다. 어시스턴트가 먼저 해야 할 일은 **그 둘을 가르는 것**이다.

## 🔴 한 주제 안에도 커버리지 공백이 있다

문서 10건 중 **D8(앱 버전)·D9(동반 이동)·D10(알림 기준)에는 추천 문구가 하나도 닿지 않는다.**
추천 10개가 나머지 7건에 몰려 있다.
→ 사용자는 이 세 문서에 **추천을 따라가는 경로로는 절대 도달하지 못한다.**
→ 이것이 「선제안/추천 질문 콘텐츠 운영」이 할 일의 최소 단위다 —
없는 문서를 만드는 게 아니라 **있는 문서로 가는 문구를 만드는 것.**

## 🔴 왜 FAQ를 정답 문서로 삼았나 — 이게 이 실험의 가장 큰 한계다

제대로 하려면 **약관·상품설명서 같은 1차 금융 문서**를 파싱하고 전처리해서 쓰는 것이 맞다.
길고, 조·항·호로 구조가 있고, 청킹과 버전 관리가 실제로 필요해지는 것도 그쪽이다.

**그런데 우리는 그 문서의 정답을 판단할 수 없다.**

D-03이 *"정답은 사람이 직접 붙인다"* 인데, 약관 조항 중 *"이 질문의 정답은 제12조 3항"* 을 붙이려면
**금융 실무 지식이 필요하다.** 우리에게 그 지식이 없다. 우리가 붙이면 **라벨부터 틀리고,
라벨이 틀리면 그 위에 쌓은 수치가 전부 무의미해진다.**

그래서 **공개 FAQ를 정답 문서로 삼았다.** 근거는 둘이다.

| | |
|---|---|
| **카카오뱅크가 공식으로 답한 내용이다** | 우리가 판단한 것이 아니라 은행이 확정한 사실이다. 라벨을 붙일 때 우리 지식이 필요 없다 |
| **AI가 실제로 이 문서를 쓴 정황이 있다** | FAQ 원문 `2.41 버전 이상부터 이용 가능` ↔ AI 답변 `2.41 미만이라 메뉴 접근/이용이`. 관측 204턴에서 약관은 2회, 설명서는 2회만 언급됐다 |

⚠️ **다만 이것이 「FAQ = 카카오뱅크의 실제 RAG 문서」를 증명하지는 않는다.** 겹친다는 것까지만 말할 수 있다.

⚠️ 그리고 **FAQ는 쉬운 문서다.** 한 건이 34~715자라 **이미 한 조각**이고, 그래서 우리는
**청킹도 버전 관리도 다뤄보지 못했다.** 긴 문서에서 필요해지는 근육을 못 썼다는 뜻이다.

→ *"시간이 없어 줄였다"* 가 아니다. **시간이 열 배 있어도 우리가 약관의 정답을 판단할 수는 없다.**
할 수 있는 것과 할 자격이 있는 것을 갈라 고른 결과다.

## 🔴 문서에 넣은 문구의 28/35는 우리가 지어낸 말이다 (2026-08-22 확인)

재작성 원칙 A를 **「사용자가 실제로 쓴 말을 넣는다」** 라고 적었는데 두 가지가 틀렸다.

1. 재료는 사용자가 지어낸 말이 아니라 **앱이 추천으로 띄운 문구**다. 관측자는 프로토콜대로 타이핑했을 뿐이다.
2. 그리고 실제로 넣은 문구 **35개 중 28개는 관측 기록에 없다.** 우리가 만들어 넣었다.

```
문서에 넣은 문구 35개    관측  7 · 창작 28
  1차 자동이체 30개      관측  2 · 창작 28      <- 창작이 여기 몰려 있다
  2차 적금      5개      관측  5 · 창작  0

채점에 쓴 질의 25개      전부 관측 실재 · 창작 0
```

→ **1차의 `4/7 → 7/7` 은 이 창작 문구까지 얹힌 값이다.** 훈련/검증을 안 나눈 것에 더해 재료 자체도 오염됐다.
→ **2차는 넣은 문구가 전부 관측 실재**이고 분할도 했다. 이 문서에서 신뢰할 값은 2차 쪽이다.
→ 문서를 고쳐 다시 돌리지 않은 이유와 전수 표는 [`data/rag/docs-v2/_문구출처.md`](../data/rag/docs-v2/_문구출처.md)에 적었다.

## 이 실험이 못 하는 것

- **문서 10건은 작다.** 임베딩이 쉽게 만점을 냈고, 문턱의 여유도 이 크기에서만 성립한다
- **문서를 쪼개지 못했다.** D1(715자·※8개)은 쪼개는 것이 옳아 보이지만
  쪼개면 정답 라벨이 깨져 비교가 성립하지 않는다 → **다음 실험으로 넘긴다**
- **답변 생성은 재지 않았다.** 검색이 맞아도 AI가 잘 쓴다는 보장은 없다.
  우리는 카카오뱅크 파이프라인에 문서를 넣을 수 없다 — **검색 단계까지가 우리가 잴 수 있는 전부**다
- **라벨을 붙인 사람과 문서를 다시 쓴 사람이 같다.** 라벨을 먼저 얼려 완화했지만 없애지는 못했다
