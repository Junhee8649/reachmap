# 작업 하네스 — 무엇을 하기 전에 무엇을 돌리는가

> **규칙마다 확인할 방법을 함께 적는다. 없으면 없다고 표시한다.**
> `node tools/check.mjs` 가 이 문서를 린트한다 — 규칙 줄은 명령·파일을 가리키거나, 검증 수단이
> 없으면 ⚠️ 로 표시돼야 한다. 표시되지 않은 줄은 실패로 잡힌다.
>
> ⚠️ 가 붙은 줄은 **사람이 지켜야 하는 규칙**이고, 지켜졌는지 기계로 알 수 없다.
> 그걸 숨기지 않는 것이 이 문서의 핵심이다 — *"꼼꼼히 하자"* 류 규칙은 이미 있었고 지켜지지 않았다.

---

## 왜 문서가 아니라 명령인가

이 프로젝트에서 실제로 다친 것은 거의 전부 **숫자와 위치**였다.

| 사고 | 실제 |
|---|---|
| AI 기능 `6개`로 확정 | 7개. FAQ 카테고리 수를 기능 수로 오인 |
| S06 재탕 `6건` | 5건. 손으로 세고 확인 안 함 |
| S12 분기 `3턴 ②번` | 3턴 ③번. `CLAUDE.md` 메모를 열지 않고 옮겨 적음 |
| 관측 원문을 `메모` 칸에 | 요약만 들어가고 원문이 사라짐 |

전부 **"확인했다고 생각하고 확인하지 않은 것"** 이다.
`CLAUDE.md` 작업규칙 2는 이미 *"모르는 것은 추측하지 말고 물어본다"* 인데도 같은 일이 반복됐다.
**산문 규칙은 이 종류의 실수를 못 막는다.**

## 작업별

### 관측을 기록할 때

| 순서 | 무엇 |
|---|---|
| 1 | 지시는 `node tools/plan.mjs <시드>` 로 출력한다. 기억으로 말하지 않는다 |
| 2 | 받은 원문을 **먼저** `data/raw/round2/<시드>-r<회차>.txt` 에 가공 없이 저장한다 |
| 3 | 그 다음 CSV를 쓴다. 읽고 쓰기는 `tools/lib/csv.mjs` 의 `readCsv`·`writeCsv` 로만 한다 |
| 4 | 쓴 뒤 `node tools/plan.mjs` 로 행수·기록 상태를 확인한다 |

- 분기 규칙은 `docs/03-관측-프로토콜.md` 의 「분기탐색 규칙」 절이 유일한 출처다
- ⚠️ 관측이 시작된 배치 안에서는 규칙을 바꾸지 않는다. 바꿔야 하면 **그 배치를 끝내고** 바꾼다

### 데이터 파일을 고칠 때

| 순서 | 무엇 |
|---|---|
| 1 | 고치기 전에 무엇이 바뀌는지 먼저 말한다 (`CLAUDE.md` 작업규칙 4) |
| 2 | 기준선을 뜬다 — `data/scored-round1.json` 을 임시 위치에 복사 |
| 3 | 고친 뒤 `node tools/score.mjs` 를 돌려 턴수·딥링크·룰 6종·재탕 3층을 기준선과 대조한다 |
| 4 | 행수·컬럼수는 `Import-Csv` 또는 `readCsv` 로 센다. 눈으로 세지 않는다 |

- ⚠️ 관측 원문의 글자는 바꾸지 않는다. 쉼표·따옴표는 CSV 인용으로 처리한다
- 원문 파일에는 관측된 것만 둔다. 설명·경고는 `data/raw/round1/_manifest.json` 으로 옮긴다

### 문서를 쓸 때

| 순서 | 무엇 |
|---|---|
| 1 | 수치·위치·문구를 쓰기 전에 해당 파일을 연다 (`CLAUDE.md` 작업규칙 3) |
| 2 | 다 쓰고 `node tools/check.mjs` 를 돌린다 — 숫자 주장, 경로 실재, 과장 표현을 본다 |
| 3 | ⚠️ 과장 목록에 걸린 줄은 근거가 계산되는지 확인하고, 안 되면 표현을 낮춘다 |

- ⚠️ 같은 절에 「개정 → 재개정」이 두 번 쌓이면 그 절을 다시 쓴다. 층을 더 얹지 않는다
- 새로 만든 수치는 `tools/check.mjs` 의 `주장` 표에 추가한다. 안 넣으면 다음에 또 틀린다

### 커밋할 때

| 순서 | 무엇 |
|---|---|
| 1 | ⚠️ 작업 단위로 묶는다 — 관측은 목적 단위(재현성·분기탐색·인계조건), 도구는 검증이 끝났을 때 |
| 2 | 커밋 전에 `node tools/check.mjs` 와 `npx tsc --noEmit` 를 돌린다 |

- ⚠️ 같은 세션에서 방금 쓴 것을 다듬은 것은 별도 커밋으로 남기지 않는다
- ⚠️ 남이 지적해서 고친 것은 별도 커밋으로 남긴다. 그건 과정이다

## 검증을 어디서 멈추나

검증기를 검증하고 그것을 또 검증하면 끝이 없다. 멈추는 기준은 둘이다.

| 기준 | 뜻 | 예 |
|---|---|---|
| **자기보다 단순한 것으로만 검증한다** | 기댓값은 계산이 아니라 손으로 쓴다 |  자체검증 |
| **독립 경로 둘이 일치하면 멈춘다** | 층을 쌓지 않고 옆에서 대본다 | 우리 파서 110행 ↔ PowerShell  110행 |

**무엇에 테스트를 붙일지도 기준이 있다.**

| | 테스트 |
|---|---|
| 조용히 틀리는 것 — 잘못돼도 그럴듯한 값이 나온다 | 붙인다 (파서·채점 룰) |
| 시끄럽게 틀리는 것 — 틀리면 화면에 바로 보인다 | ⚠️ 안 붙인다 ( 같은 보고 도구) |

는 만들자마자 오탐을 두 번 냈고 **돌려서 읽는 것만으로 즉시 잡혔다.**
거기에 자체검증을 더 얹는 것이 무한 반복의 첫 계단이다.

## 검증을 어디서 멈추나

검증기를 검증하고 그것을 또 검증하면 끝이 없다. 멈추는 기준은 둘이다.

| 기준 | 뜻 | 예 |
|---|---|---|
| **자기보다 단순한 것으로만 검증한다** | 기댓값은 계산이 아니라 손으로 쓴다 | `tools/lib/csv.mjs` 자체검증 |
| **독립 경로 둘이 일치하면 멈춘다** | 층을 쌓지 않고 옆에서 대본다 | 우리 파서 110행 ↔ PowerShell `Import-Csv` 110행 |

**무엇에 테스트를 붙일지도 기준이 있다.**

| 종류 | 테스트 |
|---|---|
| 조용히 틀리는 것 — 잘못돼도 그럴듯한 값이 나온다 | 붙인다 (`tools/lib/parse.mjs`·`tools/lib/rules.mjs` 같은 파서·룰) |
| 시끄럽게 틀리는 것 — 틀리면 화면에 바로 보인다 | 안 붙인다 (`tools/check.mjs` 같은 보고 도구) |

`check.mjs`는 만들자마자 오탐을 두 번 냈고 **돌려서 읽는 것만으로 즉시 잡혔다.**
거기에 자체검증을 더 얹는 것이 무한 반복의 첫 계단이다.

## 이 하네스가 못 막는 것

| 못 막는 것 | 왜 |
|---|---|
| 논리 오류 | `4턴까지 안 보이면 3턴에서 고른다` 는 시간 역행인데 어떤 검사도 안 잡았다 |
| 같은 원인의 미전파 | 슬롯이 밀린다는 것을 알고도 턴에는 적용하지 않았다 |
| 문서가 길어지는 것 | 줄 수는 셀 수 있어도 「불필요한지」는 못 센다 |

**셋 다 사람이 다시 읽어야 잡힌다.** 검사기는 이 목록을 줄여주지 못하고, 줄여준다고 믿으면 더 위험하다.
